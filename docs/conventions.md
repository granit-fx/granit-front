# Front-end Conventions

Conventions for the `@granit/*` front-end framework that linters and arch-tests
do not (yet) fully enforce. See also each repo's `CLAUDE.md` and the backend
guide under `granit-dotnet/docs/guide/conventions/frontend/`.

## Component placement & naming (`@granit/react-ui-*`)

In the UI tier, **the directory says which layer a file belongs to; the filename
suffix says what role the component plays.** The two are orthogonal and both
carry information — neither makes the other redundant.

### Directory = layer

Presentational components all live under `src/components/`, never loose at the
`src/` root. The root is reserved for non-component concerns:

```text
packages/@granit/react-ui-{module}/src/
├── components/        # ALL presentational components (see role suffixes below)
├── locales/           # i18n bundles (en.ts, fr.ts)
├── constants.ts       # static config
├── validation.ts      # spec-driven resolver factories (no zod — see below)
├── __tests__/         # tests (or co-located *.test.tsx next to each component)
└── index.ts           # the single barrel — the only public entry point
```

A page/dialog/form left at `src/` root when a `components/` dir exists is an
inconsistency: move it under `src/components/`.

### Suffix = role

Inside `src/components/`, the filename suffix marks the component's role. This
taxonomy is used uniformly across the tier:

| Suffix      | Role                                        |
| ----------- | ------------------------------------------- |
| `*-page`    | full page / route-level view                |
| `*-dialog`  | modal dialog / sheet                        |
| `*-form`    | form (spec-driven resolver, see below)      |
| `*-columns` | `ColumnDef<T>` definitions for a data table |
| `*-card`    | card / tile                                 |
| `*-badge`   | status badge / pill                         |
| `*-table`   | table / grid                                |
| `*-tab`     | tab panel                                   |
| `*-actions` | row/toolbar action cluster                  |

**Keep the role suffix even though the file is under `components/`.** The
directory tells you it is presentational; the suffix tells you _which kind_. A
`parties-list-page.tsx` next to `add-email-dialog.tsx` and `party-columns.tsx`
reads at a glance — dropping `-page` would lose that and break consistency with
every other `*-page` in the tier.

### File casing

All component files are `kebab-case.tsx`; the exported React symbol is
`PascalCase` (e.g. `parties-list-page.tsx` exports `PartiesListPage`).

## Three-layer separation

Every domain spans three packages with a strict one-way dependency direction:

```text
@granit/{module}           core    — types/ + api/ (Axios) + permissions.ts, NO React
        ▲
@granit/react-{module}     headless — hooks/ + providers/ + testing/, NO admin pages
        ▲
@granit/react-ui-{module}  UI      — components/ on @granit/react-ui, NO data access
```

The UI tier performs no data access: no `api/` dir, no Axios/`@granit/api-client`
runtime dependency, no domain `fetch`. Data flows through the headless hooks.
Generic HTTP error guards (`isAxiosError`, `HttpError`) are re-exported by the
headless package so the UI never imports `@granit/api-client` directly.

## Forms are spec-driven (no zod)

Form validation is **derived from the OpenAPI contract**, not hand-written zod.
Use `createConstraintsResolver(<module>Constraints.<Dto>, t, { labelResolver })`
from `@granit/react-validation`, fed by the generated `src/constraints.ts` in the
core package (regenerated by the pre-commit hook from `contracts/openapi/*.json`
— never hand-edit it). Client-only checks the spec cannot express (email/phone
format, cross-field rules, URL/FQDN) are layered on top of the spec resolver as
augmentations. `zod` and `@hookform/resolvers` are not used in the tier.
