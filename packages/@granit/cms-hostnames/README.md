# @granit/cms-hostnames

Framework-agnostic **CMS hostname** SDK — the TypeScript counterpart of the .NET
`Granit.Cms.Hostnames.Endpoints` module. It exposes the site-scoped DTOs, the Axios
HTTP client and the spec-derived validation constraints needed to drive hostname
management for a CMS site from any client (React, React Native, a CLI, tests). It
holds **no** React, DOM or Node-only dependency.

These are the **narrow, site-scoped CMS** contracts (`/api/cms/sites/{siteId}/hostnames`),
distinct from the generic platform hostname contract in
[`@granit/hostnames`](../hostnames). The React hooks + provider layer lives in
[`@granit/react-cms-hostnames`](../react-cms-hostnames); the admin feature kit (list
page, add-hostname form, status badge, verify/remove actions) in
[`@granit/react-ui-cms-hostnames`](../react-ui-cms-hostnames). The DTOs mirror
`contracts/openapi/cms-hostnames.json`, the authoritative source for routes, methods,
status codes and field optionality.

## Install

Workspace-internal — consumed via the `@granit/*` Vite/Vitest aliases. Declare these
peers in the consuming package:

- `@granit/api-client` — the centralized Axios client (CSRF, auth, tenant interceptors)
- `@granit/types` — branded primitives (`ISODateString`)
- `@granit/validation` — `SchemaConstraints` (consumed by the generated constraints)

## Quick start

```ts
import {
  addSiteHostname,
  checkSiteHostnameAvailability,
  listSiteHostnames,
  verifySiteHostname,
} from '@granit/cms-hostnames';

// `basePath` is the API origin/prefix; `siteId` is the CMS site Guid. The
// collection root resolves to `{basePath}/api/cms/sites/{siteId}/hostnames`.
const hostnames = await listSiteHostnames(client, basePath, siteId);

// Pre-check before claiming (debounce while typing — a malformed FQDN is a 400).
const { available } = await checkSiteHostnameAvailability(
  client,
  basePath,
  siteId,
  'www.acme.com'
);

if (available) {
  // Register and start DNS verification. `isPrimary` defaults to false.
  const created = await addSiteHostname(client, basePath, siteId, { host: 'www.acme.com' });

  // Later: re-run the DNS check after the owner configures `expectedDnsRecords`.
  const refreshed = await verifySiteHostname(client, basePath, siteId, created.id);
}
```

## Public API

| Symbol                             | Kind  | Purpose                                              |
| ---------------------------------- | ----- | ---------------------------------------------------- |
| `SiteHostnameResponse`             | type  | A managed hostname (status, primary flag, DNS, TLS)  |
| `SiteHostnameDnsRecordResponse`    | type  | One DNS record the owner must configure to verify    |
| `SiteHostnameDnsRecordType`        | type  | DNS record type enum (`A`, `Aaaa`, `Cname`, `Txt`)   |
| `SiteHostnameAvailabilityResponse` | type  | Availability pre-check result (`host` + `available`) |
| `SiteHostnameCreateRequest`        | type  | `POST` body — `host`, `isPrimary?` (defaults false)  |
| `listSiteHostnames`                | fn    | `GET .../hostnames` — `Cms.Sites.Read`               |
| `checkSiteHostnameAvailability`    | fn    | `GET .../availability?host=` — `Cms.Sites.Read`      |
| `addSiteHostname`                  | fn    | `POST .../hostnames` (201) — `Cms.Sites.Manage`      |
| `removeSiteHostname`               | fn    | `DELETE .../hostnames/{id}` — `Cms.Sites.Manage`     |
| `verifySiteHostname`               | fn    | `POST .../{id}/verify-now` — `Cms.Sites.Manage`      |
| `cmsHostnamesConstraints`          | const | Spec-derived validation constraints (generated)      |

## Out of scope / caveats

- **Generated constraints.** `cmsHostnamesConstraints` is generated by
  `scripts/generate-front-constraints.mjs` from `contracts/openapi/cms-hostnames.json`
  on pre-commit — **never edit it by hand**. Feed it to `createConstraintsResolver`
  from `@granit/react-validation` (the form wiring lives in the react-ui layer).
- **Backend is authoritative.** The permission gates above (`Cms.Sites.Read` /
  `Cms.Sites.Manage`) are documentation of the server's enforcement, not a client
  check — every call is re-authorized by `Granit.Cms.Hostnames.Endpoints`. Global
  hostname uniqueness, DNS provisioning and TLS issuance happen edge-side; this SDK
  only surfaces their reported state (`status`, `certificateStatus`,
  `expectedDnsRecords`, `lastCheckedAt`).
- **Not the generic hostname contract.** Do not mix these DTOs with
  [`@granit/hostnames`](../hostnames) — they target different routes and aggregates.
- **No React.** Caching, query keys and provider config are the job of
  [`@granit/react-cms-hostnames`](../react-cms-hostnames); UI is
  [`@granit/react-ui-cms-hostnames`](../react-ui-cms-hostnames).
